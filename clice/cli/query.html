On this page

Query ​

Overview ​

clice query asks the persisted index a structured question and prints the answer as JSON on stdout — for scripts and coding agents that want the facts a language server has without speaking LSP. It reads the index straight from disk, the same index clice index builds and an editor session keeps up to date, so it works while the editor is open and needs no server when it is not.

Usage: clice query <question> [<locator> | <file>] [--workspace <dir>] [--configuration <tag>] [--fresh] [question options]

Questions ​

  • symbol-search [<locator>] [--limit <n>] lists the symbols a locator matches, best first, with their kind, file, line, container and symbol, and for a function the signature that tells its overloads apart. A symbol several places define — a weak function and its strong one, the main of each program — is listed at each definition, and a macro no file defines at <command line> (a -D of the compile command) or <built-in> (the compiler's own).
  • definition <locator>, read-symbol <locator>, references <locator> [--include-declaration], call-graph <locator> [--direction callers|callees|both], type-hierarchy <locator> [--direction supertypes|subtypes|both] and implementation <locator> answer about the one symbol the locator names: definition gives its declaration when nothing defines it, its other definitions as otherDefinitions when several places define it and <command line> or <built-in> for a macro no file defines, each reference names the function it lies in, and implementation lists the classes deriving from a class, or the overrides of a function, at every level below it. A locator several symbols match lists them as candidates; a name none spells exactly, case included, names no symbol and lists the closest matches the same way, even one. definition and read-symbol also give the symbol's documentation: its documentation comment as markdown, read as the editor's hover reads it — @param, @return and @copydoc resolved, an undocumented override showing what it overrides.
  • document-symbols <file> is the file's outline.
  • project-files [--filter all|source|header|module] lists the build's files; file-deps <file> [--direction includes|includers|both] [--depth <n>] follow the include graph, and impact-analysis <file> the include graph and the files that import a module the file is part of.
  • counterparts <file> lists the files the file pairs with — a header's sources, a source's headers, a module's interface and implementation units — best first, each with its reasons, and names the one an editor would open without asking as preferred (see Switch Source/Header).

Paths are relative to the current directory or absolute in questions, absolute in answers; lines are 1-based.

Locators ​

A locator names symbols, wherever a command takes one. It is one string: spaces separate its terms, quotes and angle brackets keep theirs. One term names the symbol, the others narrow the answer.

LocatorFinds
foonames matching foo as a subsequence aligned to their words — LinLis finds LinkedList, up finds unique_ptr — the exact name first, then the names starting with the query, then the rest; six letters or more also find names one typo away, last
"foo"the whole name, case-sensitive
foo*, *_test, get?Namenames the glob matches, case-sensitive once the pattern has an uppercase letter
ns::Foo::barsymbols inside a container whose chain lists ns and Foo in that order, other containers allowed around them
::ns::Foo::barsymbols inside exactly that container
ns::*, ns::**the container's members; everything below it
Widget<int>the specialization spelling those arguments
#1a2b3cthe symbol with that id; one only some files see takes path: naming a file that holds it, relative or absolute
src/a.cpp:120the symbols defined on that line
src/a.cpp:120:8the symbol under that cursor, with a 1-based line and byte column
kind:function,methodonly these kinds
path:src/index/symbols declared in that file or under that directory, a path relative to the current directory; a bare file name, path:a.cpp, matches every file of that name

A local or a parameter is known only to its file: a name finds it only together with path: naming the file or its directory. An entity of internal linkage at namespace scope — static, or in an anonymous namespace — a name finds wherever it is.

Every symbol an answer lists carries symbol, a locator naming it back: its id, followed by path: and its file for a symbol only some files see. Pass it back as it is. On a shell command line, quote the whole locator: # there starts a comment, < and > redirect and * expands.

Answers ​

Every answer is one JSON object: {"result": ..., "stale": [...]} on success, {"error": "...", "stale": [...]} with exit code 1 when the question cannot be answered (an unknown symbol, a file that does not exist, a negative --depth), or 2 when the arguments do not parse (an unknown question, a locator or file missing or too many, a --filter or --direction value that is none of the listed ones) or the project or its index cannot be read (no project, a configuration that does not parse, a damaged index database). An error for a locator that matched several symbols lists them in candidates, each with its symbol.

stale lists the files whose entries the answer had to leave out because their content on disk no longer matches what was indexed — the positions the index holds for them would point into text that moved. A file that changed only because a header it includes changed keeps answering from its last index. A symbol whose definition sits in a stale file is reported as not found, with the file named, so a reader can tell "does not exist" from "not indexed yet". Only files the answer consulted are checked: a symbol added to a file after it was indexed is simply absent, since no entry leads to that file — --fresh is the way to ask about the current disk. The index never sees unsaved editor buffers: the disk is the truth it describes.

--fresh brings the index up to date with the disk before answering: while an editor session has the project open, its server runs the sweep; otherwise the command runs the indexer itself, building the index from nothing when there is none yet. Either way only the units whose inputs changed are recompiled. Without --fresh a project with no index answers with an error.

Documentation

Supported

A symbol nothing defines

Supported

Answers through instantiations

References and the call graph include what instantiations and macro expansions resolve, each marked with its via

A use the written code leaves open — a dependent call in a template, a name in a macro body — answers with "via": "instantiation" or "via": "expansion"; the written code's answers carry no via. A caller carries one only when instantiations make all its calls.
